1. Introdução

Este documento descreve o projeto Gerenciador de Tarefas, desenvolvido por Antonio Pignataro (trabalho individual) para a disciplina Projeto de Desenvolvimento de Software I e II. O objetivo é projetar e implementar um sistema de software completo, passando pelo levantamento de requisitos, pela modelagem com diagramas da UML e do modelo de dados e pela implementação com acesso a banco de dados.

O Gerenciador de Tarefas é uma aplicação web para organização de afazeres pessoais. O usuário cadastra tarefas com título, descrição e prazo, agrupa-as em categorias (por exemplo, "Faculdade", "Casa" ou "Trabalho"), acompanha quais estão pendentes ou concluídas e pode editar ou excluir qualquer registro. O sistema contempla as quatro operações de CRUD (Create, Read, Update, Delete) sobre duas entidades: Tarefa e Categoria.

1.1 Tecnologias utilizadas (stack)

  • Linguagem: Python 3;
  • Framework web: Flask, responsável pelas rotas e pela renderização das páginas com o motor de templates Jinja2 (PALLETS PROJECTS, [s. d.]);
  • Banco de dados: SQLite (relacional) (SQLITE, [s. d.]), acessado pelo módulo sqlite3 da biblioteca padrão do Python (PYTHON SOFTWARE FOUNDATION, [s. d.]);
  • Front-end: HTML5 e CSS3 simples, sem bibliotecas externas;
  • Testes: módulo unittest com o cliente de testes do Flask;
  • Controle de versão: Git e GitHub.

1.2 Escolha do tema e das tecnologias

O tema foi escolhido por ser de fácil entendimento e por permitir exercitar todos os conceitos pedidos com poucas entidades. As tecnologias foram escolhidas pela simplicidade: o SQLite dispensa a instalação de um servidor de banco de dados e o Flask permite construir a aplicação com poucos arquivos, o que facilita a execução e a avaliação do projeto.

4.2 Diagrama Entidade-Relacionamento (DER)

O modelo de dados, elaborado segundo a abordagem entidade-relacionamento (ELMASRI; NAVATHE, 2018), possui duas entidades. Uma categoria pode classificar várias tarefas (relacionamento 1:N) e cada tarefa pertence a no máximo uma categoria, pois a chave estrangeira é opcional. Ao excluir uma categoria, a chave estrangeira das tarefas é definida como nula (ON DELETE SET NULL).

4.3 Diagrama de Classes

O diagrama de classes está focado nas entidades do domínio. A classe Tarefa referencia a classe Categoria; uma categoria pode ter zero ou mais tarefas.

5.2 Como executar

  1. Instalar as dependências: pip install -r requirements.txt;
  2. Executar: python app.py (o banco tarefas.db é criado automaticamente);
  3. Acessar http://127.0.0.1:5000 no navegador;
  4. Rodar os testes: python -m unittest discover tests.

6. Conclusão

Com este projeto foi possível percorrer, na prática, as etapas principais do desenvolvimento de um software: levantar requisitos funcionais e não funcionais, modelar o comportamento com casos de uso, atividade e sequência, modelar os dados com o DER e o diagrama de classes e, por fim, implementar o sistema de acordo com essa documentação.

O principal aprendizado foi perceber como a modelagem antecipa decisões da implementação: o DER definiu diretamente as tabelas e a chave estrangeira, e os diagramas de sequência indicaram quais rotas e consultas SQL seriam necessárias. Também foi importante tratar casos de erro, como o título vazio e o nome de categoria repetido, e decidir o que acontece com as tarefas quando uma categoria é excluída. Por fim, os testes automatizados mostraram que é possível verificar o CRUD de forma rápida e repetível.

Como melhorias futuras, o sistema poderia ganhar autenticação de usuários, prioridades para as tarefas, lembretes de prazo e uma API para integração com aplicativos móveis.
